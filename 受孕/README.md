# 子宫孕育（astrbot_plugin_conception）1.35.239

给角色加一条"身体线"：**快感值 → 高潮 → 体内射精 → 受孕判定 → 验孕 → 十个月孕期**。
受孕成功后，孕期状态会写进日常提示词，同时把 `private_companion` 的月经周期
置为"不生效"，十个月内不再出现经期。

只在**主人私聊**里工作；群聊、陌生人、成人层没打开时一律静默。

自带 Web 面板：在 AstrBot 侧边栏「扩展功能」里点 **受孕**，可以看到快感/连续高潮、
受孕概率分解、生理期、孕期进度、联动数据和最近事件，也能直接点按钮操作。

## 1.14.8 修复

### 写 PC 状态改成"只改我们那一点"，不再整份覆盖（顺手修了她被写成 0 的精力）

**现象**：「我会永远陪着你」插件页面的「当前能量」显示 **0 / 100**。

**查证**：面板没画错，库里那条记录的 `values.energy` 就是 0。她的角色记录在
16:10:33 由 PC 自己写过一次（revision 258，同一 revision 的历史里 `energy = 78`），
之后 `role_state_records` 里**同一个 revision** 的 JSON 被"只改了 energy"地覆盖成 0
——这种"不涨 revision、不留历史"的写法，整套插件里只有本插件会做
（`角色周期暂停/孕期状态/精力调整`）；PC 自己走的是版本化仓储，会同时写历史。
所以是我们某次写 PC 状态时把旧的整份记录盖了回去。

**改法**：

- `core/pc_cycle.py` 新增 `patch(db, owner_key, revision, changes)`：
  **在同一个事务里"读最新记录 → 只改 changes 里列出的字段 → 写回"**，
  `values` 是逐字段合并（`{"values": {"energy": 70}}` 只动 energy），`值 = None` 表示删键；
  revision 不对就整次放弃（不会再整份覆盖别人的新值）；
- `pc_state.sync_pregnancy / clear_pregnancy / adjust_energy`、
  `pc_cycle.suppress / restore` 全部改用 `patch()`，只提交要改的字段；
- 新增自检 `test_pc_patch()`：只改 energy 时别的字段原样、只改 conditions 时 energy 不被带回、
  旧 revision 会被拦下且不写坏数据。

**数据修复**：已把这条记录里被写成 0 的 `energy` 按 PC 自己那份（同 revision 的历史 78）
修回去；`busy / hunger / mood / conditions` 等其它字段原样未动。

- 「保存并返回」点过之后同样不受这个 10 秒影响，走它自己的 20 秒限时；
- 顺手加了个兜底：按钮已经变「保存成功」但页面 1.5 秒后还没关掉，就强制关闭，
  不会把弹窗卡在「保存成功」上（截图里那种情况）。

## 1.14.6 修复

### 弹窗「保存并返回」加了 20 秒限时和按钮状态

点「保存并返回」后：

| 情况 | 表现 |
|---|---|
| 按钮 | 立刻变成「**保存改动中…**」，三个按钮暂时置灰，防连点 |
| 20 秒内保存成功 | 按钮变「**保存成功**」→ 约半秒后正常返回 |
| 20 秒内保存失败 | 按钮变「**保存失败，点这里重试**」，弹窗留着（可以重试或选「不保存返回」），状态栏写原因 |
| **超过 20 秒** | 弹窗和页面**先正常返回**，随后飘一条「**仍在保存中…**」淡出；等慢请求真正落地后，再飘一条「**已保存**」或「保存没成功：原因」淡出 |

后面这两条"落地提示"只在超时返回这条路径出现（正常成功就是按钮变「保存成功」后返回，不再额外飘）。

点「保存这三段」还是等 8 秒回执，超时提示「已提交，回执有点慢」。

## 1.14.5 修复

### 服务端慢也不卡：切部位 / 返回改成"后台写入"，并加「正在保存改动」状态

1.14.4 里切部位和「保存并返回」都要**等保存回执**，服务端一慢就被拦住（只有点「保存这三段」慢慢等才成功）。
现在：

- **切部位 / 切页签 / 保存并返回 / 关页面**：把这一页的字发出去就立刻走，不等回执；
- **草稿记忆**：没确认写进服务端之前，切走再切回来显示的还是你刚敲的字（不会看到旧文本）；
- **状态徽标**（就是「已保存 16:07:19」那个位置）现在会走这几个状态：
  - `正在保存改动…`（有后台保存在路上，切部位后也能看到）
  - `已保存 16:07:19`
  - `16:07:19 已存上一处；当前这段还没存`
  - `有 N 处没存上：回到那一段点「保存」重试`（同时弹提示）
- **点「保存三步」仍然等回执**（最多 8 秒）：成功 → 已保存；服务端太慢 → "已提交，回执有点慢"（不判失败）；
  失败 → 红字说明，字还留在输入框里，可以重试；
- 修了一个隐蔽 bug：**晚到的后台回包会把别的页的"未保存"标记抹掉**，
  导致「返回」时该弹的确认框不弹——现在脏标记在发请求前就结算，且只认当前页。

后端本身很快（实测整份面板数据 2ms、保存 1ms），慢是在 HTTP 链路上，所以这版只改前端。

## 1.14.4 修复

### 编辑页不再把输入框里的字改回去 + 返回前确认

1. **保存/切换部位后文字"变回改动之前的版本"**
   最可能是**中文输入法**：点保存的那一刻，最后几个字（或标点）还在组字状态没上屏，
   读到的 `value` 就是旧文本；保存写完再把服务端的旧值写回输入框，就成了"末尾消失/变回去"。
   现在：
   - 保存前先把焦点从输入框移开（等价于点一下旁边），让输入法立刻上屏，再读值；
   - **保存后绝不把服务端文字写回输入框**（只刷"自定义"徽标和字数），输入框里永远是你敲的那份；
   - 保存后拿服务端返回的文字和刚发的比对，不一致就提示"服务端有 N 段和输入框不一致
     （可能输入法还没上屏：再点一次保存）"，不会再悄悄吞字；
   - 保存失败时切换部位/页签会被拦住（"没存上，先别切"），不会一换页就把没存上的字弄丢。
2. **有未保存的自定义提示词时点「返回」会先问一句**
   弹窗三个选择：**保存并返回 / 不保存返回 / 继续编辑**；
   - "保存并返回"会先把这段存完再关，存不上就留在页面（提示"没存上，先别走"）；
   - "继续编辑"关掉弹窗，状态栏提示还没存。
3. 顺手：保存期间「保存」按钮置灰，避免连点造成并发。

## 1.14.3 修复（提示词编辑页）

三个问题一起修了：

1. **只改一段，却被算成三段都自定义**
   根因：点「保存这三段」时会把三段**全部**写成覆盖值，哪怕其中两段和内置默认一模一样。
   现在后端判定"和默认一样 = 没改"（忽略空白/换行差异）：`set_prompts / set_prompt /
   set_method_prompt` 遇到和默认一样的内容就存空；读取时（`prompt_override`）也会把
   "其实等于默认"的旧数据当成默认——所以以前存歪的条目会**自动恢复成"内置默认"**，
   不用手动清理。面板的"阶段改过 N 段 / 自定义"数字和页签小标从此是准的。
2. **输入一个字就自动保存一次，太频繁**
   去掉了"停笔 0.7 秒自动保存"。现在打字只把状态标成「未保存…」，
   真正写入发生在：**点「保存」/ 切换部位 / 切换页签 / 点返回 / 关闭页面**。
3. **点「保存这三段」后，自定义文字的末尾会消失**
   根因：防抖保存和手动保存**并发**，旧请求后到，把旧文本（更短的那版）写回了输入框。
   现在同一时间只允许一个保存在跑（保存期间按钮置灰），切部位/返回会等它落地；
   如果保存过程中又改过字，不会用旧值覆盖输入框，并提示"保存了刚才那版；现在的改动还没存"。

### 日常小场景（自己用玩具那一小段）

不在受孕活动里、只是用一下**日常能用的玩具**时，开一个"日常小场景"：

- 窗口 `toys.daily_minutes`（默认 **20 分钟**），每用一次玩具就续一次；窗口过了就散，

- **可以升级成正常受孕场景**：日常小场景里只要出现真正的亲密动作（`intimacy_touch` /

- 面板：状态栏多一个「日常·跳蛋 12′」标签；子敏感度卡片的徽标会显示「日常中」，

| 键 | 默认 | 作用 |
|---|---|---|
| `daily_scene` | 开 | 日常用玩具会开一个日常小场景 |
| `daily_minutes` | 20 | 多久没继续就散（分钟） |
| `sub_zone` | 开 | 玩具也推高对应部位的子敏感度（日常和场景都算） |

|---|---|

| 乳头 | 揉搓 / 舔 / 吮吸 |
| 外阴 | 逗弄 / 舔 / 吮吸 |

| 肛 | 手指 / 生殖器 / 小玩具 / 舔 / 吮吸 |

```
- 尾巴（揉捏玩弄 · 第2段·发烫，49%）：尾巴被又揉又捏地玩着，尾根被攥在掌心里搓，

```

  写"动作 + 这个动作的感觉"，两句拼起来不重复；
- **谁来判方式**：优先让模型自己传 —— `intimacy_touch(zone, times, method)`，
  method 写中文（`乳交`/`揉捏玩弄`）或 key（`milk`/`knead`）都行，工具说明里列了每个部位能填什么；
  没传时系统会**从对话关键词里猜**（只在这个部位允许的方式里找，命中的词越长越优先），

不是凭空掷的，每一次判定都能在 `/受孕状态` 或 `/受孕测试` 里逐项看到：

```
P = 生理期基准概率（默认 5% ~ 40%）

    × 快感                  1 + 0.5 × 快感/100
    × 高潮次数              1 + 0.5 × min(本次次数, 5)/5
    × 体内 / 体外           体内 1.0；体外 0.002
    × 高潮时被射            高潮后 10 分钟内体内射精 ×1.8
    最后按 max_probability（默认 90%）封顶
```

生理期基准（`phase_probability`，可在配置里逐项改）：

| 阶段 | 基准 | 阶段 | 基准 |
|---|---|---|---|
| 月经期 | 5% | 排卵期 | 40% |
| 卵泡期 | 10% | 排卵前期 | 28% |
| 黄体期 | 14% | 经前期 | 6% |
| 经后恢复期 | 6% | 判不出阶段 | 15% |
| 孕期暂停 | 0% | | |

鱼之心、暗涌没启用时，对应倍率就是 ×1.00，不会用旧值硬撑：

### 生理期来源与同步

`cycle.source`：

- **auto**（默认）：优先读 private_companion 的周期；PC 不可用（没装、没启用、
  周期不是 `applicable`）时退回插件自己的 28 天模拟周期；
- **pc**：只读 PC，读不到就算"判不出阶段"；
- **own**：只用插件自己的周期，`own_*` 那几天数才生效。

选 auto/pc 时，**在 PC 面板里改的东西会自动同步过来**，不用改插件配置、不用重载：

- 每轮（最多缓存 60 秒）重读一次 PC 的 `role_state_records.cycle_clock`；
- 锚点日期、各阶段天数、手动对齐（applicability）都会跟着变；
- 连 PC 的这三条细节也照搬，算出来的阶段和 PC 自己显示的**逐日一致**：
  1. `segment_start_date` / `segment_start_number`（这一段的真实起点和周期号，

  2. `pending_plan`（周期中途改了阶段天数时，PC 会让它下个周期才生效；

  3. `variation_enabled`（PC 的"每周期轻微浮动"，用同一套 digest 算法复现）。

## 二、快感与高潮（联动）

- **高潮和快感是挂钩的**：快感到 `pleasure.orgasm_threshold`（默认 55）
  才算"真的到了"。没到这条线就调用 `intimacy_orgasm` 会被拒绝，并提示她
  "还差一点，别自己把她写成到了"。
- **高潮反作用于快感**：记一次高潮时先加 `orgasm_pleasure_gain`（25），
  再按 `orgasm_afterglow_ratio`（0.55）回落，之后有 `post_orgasm_minutes`（8 分钟）
  的"刚高潮过"状态。
- **快感会自然回落**：没人碰时每小时掉 `decay_per_hour`（8），所以隔一天
  不会还停在 90。
- **两者都影响提示词**：每轮的用户消息末尾会挂一段"此刻"，
  包含快感档位和身体感觉（平静 / 有点心浮 / 身体发热 / 快到临界 / 临界）、
  本次高潮次数、够不够到高潮、刚高潮过的敏感状态；
  模型据此写她的语气、动作和节奏，而不是只看到一个数字。

  例：
  ```
  【此刻】快感 62/100 · 身体：快到临界 · 本次已高潮 1 次 · 排卵期（第 15/28 天，PC 周期）
  （呼吸有点乱，快忍不住了，动作和语气都会更急。）
  （现在已经够到高潮了：可以调用 intimacy_orgasm 记录下来。）
  ```

### 连续高潮与"过头"

- **连续判定**：距上次高潮 `combo.window_minutes`（默认 12 分钟）内再来一次，
  就算"连续第 N 次"；超过这个窗口自动断连，重新从 1 数。
- **越来越敏感**：每连续多一次，高潮门槛就降 `combo.threshold_step`（默认 6），
  最低到 `combo.threshold_floor`（默认 38）——第二次、第三次会更容易到。
- **过头会难受**：连续到 `combo.overstim_after`（默认 3）次之后，再一次会被拦下，
  进入 `combo.rest_minutes`（默认 20 分钟）的"难受"状态：
  - 这期间 `intimacy_orgasm` 一律被拒，并明确告诉模型"她到不了了，不要写成享受"；
  - 快感增长只有平时的 `combo.pain_gain_scale`（默认 35%）；
  - 提示词会写：她身体发麻、小腹又酸又疼，碰一下都难受，会请求慢一点、停下来，
    可能会说"好难受""好痛"。
- 缓过这段时间之后自动恢复（连续计数也会因为窗口过期重新开始）。
- `/受孕高潮 强制` 可以跳过门槛和过头限制（测试用）。

### 敏感点（亲吻、抚摸）

场景里不只是"插进去"才算推进，亲、摸、揉也涨快感。每个部位独立配置：

```
一次触碰快感 = 基础快感 × (0.4 + 0.8 × 开发度/100) × 敏感度
```

- **部位**：亲吻、乳房、乳头、外阴、阴道、G点、子宫颈、肛、嘴/喉咙、耳朵、脚、尾巴
  （12 个，都能在配置里 `*_enabled` 单独关掉）；
- **开发度** `*_dev`（0–100）：越高，同一次触碰涨得越多（0 → 0.4 倍，100 → 1.2 倍）；
- **敏感度** `*_sensitivity`（倍率）：直接乘在上面；
- **基础快感** `*_pleasure`：这个部位碰一次的基准值。

触发方式：
- 工具 `intimacy_touch(zone, times)`（模型在场景里自己调）；
- 命令 `/受孕触碰 乳房 2`；
- 或场景里对话提到（`/受孕场景` 开着时，同一部位 45 秒内不重复记，
  `zones.keyword_detect = false` 可以关掉自动识别）；
- 面板「敏感点」卡片每行的涨幅可直接改：− / ＋（步进 0.5）、输入框（≥0）、
  ↺ 恢复按公式算；最右边的「碰」才是“碰一次”（加这么多快感）。
  手动改的值存在状态里，重启/高潮都不会丢。

### 子敏感度（受孕活动里才生效的第二层条）

主列表管"这个部位有多开发、有多敏感"；子敏感度管**这一场活动里她被撩到了什么程度**：

```
碰一次涨的进度 = sub_zones.gain × (0.8 + sub_zones.sensitivity_scale × 敏感度)
进度三段位：0–33% 第1段·初起 / 33–67% 第2段·发烫 / 67–100% 第3段·将溢
```

- **只在受孕活动里生效**（`sub_zones.scene_only = true`）：不在场景里不涨，
  还会按 `idle_decay_per_minute`（默认 30/分钟）很快掉回 0；
  **提示词注入也只在活动里**——场景一结束就一个字都不带（进度本身还留着）；
- **每段一句提示词**：`core/subzone.py` 里的 `LEVEL_PROMPTS`，12 个部位 × 3 段，
  都写清"她现在是什么程度"；每个部位还有**方式**提示词（`METHOD_PROMPTS`，见 1.11.0），
  两句拼成一句注入（面板「敏感点阶段性表现设置」里都能逐条改，存 state、立刻生效）；
  活动里每轮提示词带
  `【子敏感度·活动进行中】`，只带正在涨的 `prompt_zones`（默认 3）个部位；
- **满了溢出**：主敏感点 **开发度 +`burst_dev`（6）/ 敏感度 +`burst_sensitivity`（0.12）**，
  同时 **快感 +`burst_pleasure`（12）**；然后条在 `burst_fall_seconds`（2.4 秒）内
  回落到 0，回落中（`burst_cooldown_seconds`）不涨也不连爆；
- 溢出的开发度/敏感度是**叠加**的：存 `zones.<部位>.dev_bonus` / `sens_bonus`，
  盖在配置值和面板手动值上面，上限 `dev_cap` / `sensitivity_cap`；
  主列表里带加成的行，敏感度数字会变成强调色（悬停能看到加了多少）；
- **触发**：任何一次触碰都会涨（面板「碰」、`intimacy_touch` 工具、`/受孕触碰`、
  场景里对话识别），一次涨多少和这个部位的敏感度有关；
- **面板**：`sub_zones` 卡片就在「敏感点」旁边，每行是进度条 + 段位 + 当前提示词，
  「满」= 直接填满溢出一次（测试用），「↺」= 清零；
- **命令/状态**：`/受孕状态` 多一行「子敏感度」；日志里会记 `子敏感度` 两类事件
  （涨进度 / 溢出）。

### 小玩具

- 6 种：跳蛋、振动棒、吸吮器、按摩棒、肛塞、乳夹；用一次只涨快感、**不判定受孕**；
- 强度 1–3（轻柔 / 中等 / 强烈）×0.8 / ×1.15 / ×1.6；基础快感可在 `toys.*_pleasure` 改；
- 用过之后 `toys.active_minutes`（10 分钟）内提示词会记得"还在她身上"，
  面板状态栏有「玩具·X」标签，面板「小玩具」卡片能收起来（停）；
- **不在受孕活动（亲密场景）里时，只能使用部分玩具**：
  `toys.<key>_outside = true` 的才行，默认是跳蛋、按摩棒、乳夹；
  振动棒、吸吮器、肛塞要先 `/受孕场景` 或用任意亲密动作为开场景；
- 日常用这类玩具会开一个**日常小场景**（见 1.13.0）：玩具推高对应部位的子敏感度、
  可以把她弄到高潮，真正的亲密动作会把它升级成正式场景；
- 用允许的玩具不会开场景（所以真的可以"日常用"）；
- **用在哪也能选**：跳蛋可外阴/阴道/肛，振动棒可阴道/肛，吸吮器/按摩棒只能外阴，
  肛塞固定肛，乳夹固定乳头；面板每行的部位下拉、工具 `place` 参数、
  命令第三个词（`/受孕玩具 跳蛋 2 内部`）都能指定；
- 触发：工具 `intimacy_toy(toy, intensity, place)`、命令 `/受孕玩具 跳蛋 2 [部位]`、
  面板「小玩具」卡片（顶部选强度，每行「用」）、场景里对话提到（60 秒去重）。

### 射精方式与子宫容量

- **四种方式**：`vagina`（阴道内）/ `anal`（肛内）/ `throat`（深喉）/ `outside`（体外）；
- **只有阴道内会受孕**：肛内、深喉、体外都不掷骰（面板概率卡下面也写着）；
- **快感加成不同**：默认阴道内 +10、肛内 +12、深喉 +8、体外 +4，都能在
  `ejaculation.*_pleasure` 里改；
- **只有阴道内计入子宫**：每次按 `volume_ml`（默认 3 ml）上下浮动 ±35% 累加，
  超过容量（`uterus_capacity_ml`，默认 20 ml）最多到 1.5 倍，并按
  `uterus_leak_per_hour`（默认 0.4 ml/小时）慢慢吸收；
- **提示词能感知**：`/受孕状态` 和每轮的"此刻"都会写
  "子宫里大约有 12.4 ml（容量 20 ml，不少）：小腹有点发胀……"，
  分空 / 一点 / 一些 / 不少 / 快满 / 满 六档，用身体感觉而不是报数字；
- 面板「此刻」卡片里有子宫进度条，敏感点卡片里能看到每个部位的开发度/敏感度/每次涨幅。

### 寸止（吊着她）

- 快感到门槛的 `edge.min_ratio`（默认 55%）就能寸止：调用 `intimacy_edge` / `/受孕寸止`，
  不算高潮，只是停下来；
- **更渴**：每次寸止渴求 +`edge.craving_gain`（18），渴求越高触碰涨得越快
  （满渴求时 +`edge.craving_gain_bonus`，默认 35%）；
- **门槛暂时抬高**：第一次 +8，之后每次加成 ×0.7 递减，最多 +20；
- **多次后加成不明显**：第 1 次 +8、第 2 次 +13.6、第 3 次 +17.5……到上限 20 就不再涨；
- **终于到的时候更强烈**：寸止后的高潮额外加 `edge.orgasm_bonus` × 层数（上限 40），
  日志会记"被寸止 N 次后终于到了"；
- 寸止后 `edge.window_minutes`（25 分钟）没继续就消退，门槛回到正常。
- **面板可直接调**：敏感点卡片底部「下次寸止门槛加成」有 − / ＋ 和输入框，
  改的是运行时覆盖值（不用重载），点「跟随配置」恢复成 `edge.threshold_step`；
  这个覆盖值保存在状态里，高潮清空寸止层数时不会被抹掉。

### 诱发排卵

即使不在生理期的排卵期，累积到一定程度也可能把排卵"催"出来：

- 条件：本次会话高潮 ≥ `ovulation.min_orgasms`（3）**或** 快感 ≥ `ovulation.min_pleasure`（70）；
- 满足后每次高潮掷一次 `ovulation.chance`（18%）；
- 已经在排卵前期/排卵期不触发（`require_outside_fertile`），两次之间至少隔
  `ovulation.cooldown_hours`（72 小时）；
- 触发后 `ovulation.duration_hours`（24 小时）内按**排卵期**算受孕率（基准 40%），
  周期显示"排卵期（诱发）"，面板状态栏会出现「排卵中」。

## 三、亲密场景（关键词只在场景里生效）

关键词识别不是"看到词就记"，先要确认**现在真的在进行受孕活动**：

- **怎么算在场景里**（满足任一条）：
  1. 本插件自己的场景窗口：最近一次 `intimacy_pleasure / intimacy_orgasm /
     intimacy_ejaculation`、`/受孕快感 / 受孕高潮 / 受孕内射` 或 `/受孕场景`
     之后的 `adult.scene_window_minutes`（默认 30）分钟内；
  2. 鱼之心正处于成人场景里（它自己的 scene 同意或 intimate 标记）。
- **怎么开场**：在成人层已打开的前提下，模型调一次上面任一工具，或者主人发
  `/受孕场景`；每有一次亲密动作自动续场 30 分钟。
- **平常聊天不判定**：场景外，哪怕主人说"内射这个词什么意思"、她说"这剧情
  终于到高潮了"，都不会记任何东西。
- 想关掉这道门槛（不建议）：`adult.detect_requires_scene = false`，
  那就退回"成人层打开就认"。
- 手动结束：`/受孕场景 关闭`。

也就是说：`/受孕同意` 只是"允许做这件事"，**不等于**"现在正在做"；
关键词判定要求后者。

## 四、受孕之后

1. **预产期浮动**：受孕日 + 10 个自然月，再按 `pregnancy.jitter_days`（默认 10 天）
   前后随机浮动；`/受孕状态` 会标出"浮动 +3 天"这样的偏差。
2. **写进日常提示词**：受孕状态（孕几个月、第几周、预产期、这个阶段的身体与情绪
   分寸，以及"不要再来月经/PMS"）追加到 system prompt；每轮再在本轮用户消息末尾
   挂"此刻"那一段，带 `mark_as_temp`，不回存历史。
3. **经期不生效**：把 `private_companion` 的 `role_state_records.record_json`
   里 `cycle_clock` 改成
   `applicability = "not_applicable"`、`decision_origin = "manual"`。
   - 这是 PC 自己"手动对齐周期"的等价状态，它的 `cycle.project()` 会直接跳过；
   - 它的 `evolve()` 看到 `decision_origin = manual` 会保留这个值，
     所以 PC 之后自己写状态也不会把周期又打开；
   - 只改 `record_json` 一列，**不动 revision / updated_at**，不影响它的乐观锁；
   - 改之前把原 `cycle_clock` 存到 `pc_cycle_backup.json`，
     并用 SQLite 在线备份给 PC 的库留 `pc_db_backup_<时间>.sqlite3`（保留最近 2 份）；
   - 不想动库就把 `pregnancy.pc_write_enabled` 关掉，只用提示词兜底。
4. **十个月后**：到预产期自动收尾（也可以 `/受孕重置 确认` 手动结束），
   把 `applicability` 还原、锚点按"暂停了多少天"整体后移，周期从停下的地方接着走；
   之后进入 `postpartum_days`（默认 42 天）产后恢复期，恢复期分两段：
   - **前 `postpartum_hard_days` 天（默认 14）**：绝对不受孕。内射照常记，但不掷骰；
     `/受孕强制` 和面板按钮也会被拒绝；
   - **紧接着 `postpartum_low_days` 天（默认 14）**：概率乘 `postpartum_low_scale`
     （默认 0.15，即打 1.5 折），面板的倍率分解里会多一行「产后恢复期」；
   - **再往后到恢复期结束**：恢复正常判定。
   总开关是 `pregnancy.postpartum_no_conception`（默认开）：关掉就完全没有这两段保护。
5. **孕期里再做也不会重复受孕**：快感、高潮、射精照常记录（身体活动是连续的），
   但掷骰那一步直接返回「已在孕期」，不写新的受孕日/预产期；
   `/受孕强制` 和面板「强制受孕」都会回「已经在孕期了」；
   `pregnancy.start_pregnancy` 里也加了兜底，就算被误调用也只返回已有孕期。
   生产完进入恢复期；恢复期内默认不会受孕，过了那段时间（或把开关关掉）就是新一轮了。

## 五、验孕（她自己去验，再决定说不说）

对应现实里的验孕棒：

1. **起念**：每次体内射精后，有 `self_test.chance`（默认 40%）的概率，
   插件在她的"待办"里排一个验孕念头——最早 `min_delay_hours`（6h）、
   最晚 `max_delay_hours`（48h）之后。
2. **提示**：窗口到了以后，每轮"此刻"里会多一行：
   "她心里有点不踏实，想确认一下：可以调用 `pregnancy_test` 自己验；
   结果只有她知道，要不要告诉他由她自己决定。"
3. **验孕结果**（`pregnancy_test` 工具）：
   - 太早（受孕后 `early_days` 天内，默认 12 天）验，可能一条杠（假阴性，
     概率 `early_negative_chance`，默认 50%），也可能只验出很浅的两条杠；
   - 早期以外，两条杠清楚（阳性），她就算"确认"了；
   - 没怀孕就是阴性。
4. **知情与告知**：
   - 受孕时她**还不知道**，提示词只写身体反应（容易累、闻到油烟反胃……），
     并明确要求模型"不要让她直接说破"；
   - 验出阳性 / 很浅的两条杠之后，提示词会写成"她已经知道，但还没告诉他，
     要不要说、什么时候说、怎么说由她自己决定"；
   - 她的回话里一旦出现"怀孕 / 怀上了 / 两条杠 / 验孕 / 有喜"等词，
     插件就记为"已经告诉他"，提示词切换成"已经说开了"（`self_test.tell_detect`）。
   - `/受孕强制` 造出来的孕期默认也"还不知道"，可以完整走一遍验孕流程。

## 六、性别适配

读 AstrBot 人格库里的人设原文（`persona_name`，默认 `DeepSeek`；有会话人格时
优先用会话实际人格），按"性别为：女/男"、"女性/男性词"、"她/他"的弱信号打分：

- 判为女性 → 正常生效；
- 判为男性 → **整个插件不生效**（不注入、工具一律拒绝、命令只做说明）；
- 判为其他/无性别 → 不生效；
- 判不出来 → 按 `unknown_gender_policy`（默认 allow 照常生效，可改成 deny）。

也可以用 `gender_mode` 直接指定（`female / male / other / off`）跳过判断。
注意：**只读人格，不写人格**。

## 七、成人层

默认 `adult_required = true`，满足下面任一条才会记录数值、才会掷骰：

- **鱼之心的成人层总开关打开**（面板上「允许成人向身体层」，`desire.adult_enabled`）；
  默认就按这个判断——她自己的"欲≥60、关系满格、有同意/场景"是它身体层的前置条件，
  不拿来卡受孕插件。想更严可以把 `adult.fish_gate_mode` 设成 `scene`，
  那样还要求鱼之心自己有同意或场景；
- 或者本插件自己的临时授权：`/受孕同意`（默认 24 小时，可在配置里改；
  填 0 = 长期，直到 `/受孕关闭`）。

验孕（`pregnancy_test`）不受成人层限制，只要求主人私聊——毕竟这是"身体检查"。

## 九、模型工具

平时由模型在场景里自己调，不用敲命令：

- `intimacy_touch(zone, times, note)` — 亲/摸某个敏感点，按开发度和敏感度涨快感；
- `intimacy_edge(note)` — 寸止：停下来，让门槛暂时抬高、渴求上升；
- `intimacy_toy(toy, intensity)` — 用一次小玩具（跳蛋/振动棒/吸吮器/按摩棒/肛塞/乳夹）；
- `intimacy_pleasure(amount, note)` — 快感上升；
- `intimacy_orgasm(note)` — 记一次高潮（快感不到门槛会被拒绝）；
- `intimacy_ejaculation(inside, mode, note)` — 记一次射精；
  `mode` 可写 vagina/anal/throat/outside，只有 vagina 会受孕；
- `uterus_expel()` — 排出子宫里的东西（孕期拒绝，不会排胎儿）；
- `contraception_pill(action)` — 避孕药：take / stop / status；
- `contraception_condom(use)` — 戴套 / 摘套；
- `pregnancy_test()` — 她私下验一次孕；
- `pregnancy_status()` — 查当前身体状态。

关键词兜底（`adult.detect_user_message` / `adult.detect_reply`）：
主人说"射在里面"、她写到"高潮"时自动记一笔，90 秒内同一件事不重复记。
**但只在亲密场景里生效**（见第三节），平常聊天里出现关键词不会误判。

## 十一、自检

```bat
:: 纯逻辑（不需要 AstrBot 依赖）
C:\DeepSeek\Python312\python.exe selftest.py

:: 宿主环境（用 AstrBot 的 venv 载入插件、跑一遍注入/验孕/告知）
C:\DeepSeek\AstrBot\.venv\Scripts\python.exe selftest_host.py
```

两个脚本都不会写真实数据：`selftest.py` 的 PC 库操作全部在临时副本上做，
`selftest_host.py` 的状态文件在临时目录，配置里也关掉了 PC 写入。

## 十二、回滚

1. 插件配置里关掉 `pregnancy.pc_write_enabled`，再 `/受孕重置 确认`；
2. 或者直接用 `pc_db_backup_<时间>.sqlite3` 覆盖
   `...\astrbot_plugin_private_companion\installations\main\runtime\companion-v2.sqlite3`
   （覆盖前先停 AstrBot）；
3. 只想让它不干活：关总开关，或 `gender_mode = "off"`。

## 十四、Web 面板

插件自带一个页面，AstrBot 侧边栏「扩展功能 → 受孕」点进去就是（需要管理员登录）。

- 文件：`views/conception/`（4.29+ 优先扫 `views`）；`pages/conception/` 是旧版本兼容副本，
  改完页面跑一次 `tools/sync_pages.py` 保持两份一致；
- 标题：`.astrbot-plugin/i18n/zh-CN.json` 里的 `views.conception.title`
  （同时写了 `pages.conception.title` 兜底）；
- 数据接口：`GET /astrbot_plugin_conception/web/state`；操作接口：
  `POST /astrbot_plugin_conception/web/action`（另带 `/conception/web/...` 别名）。
  **路径故意用三段**：面板按完整路径逐条正则匹配、先匹配到谁用谁，
  而鱼之心用的是 `/<plugin>/state` 两段通配路由；两段路径会被它抢走
  （加载顺序一变就翻车），三段它匹配不到；
- 面板里能做的操作：快感 +12 / 记一次高潮 / 体内射精 / 体外 / 验孕 / 排出子宫 /
  吃停避孕药 / 戴摘避孕套 / 授权 24h /
  撤掉授权 / 进入场景 / 结束场景 / 强制受孕 / 重置孕期与周期；
- 「敏感点」旁边是「子敏感度」卡片：只在受孕活动里涨，条满了溢出一次
  （给主敏感点加开发度/敏感度 + 快感），随后几秒内退回 0；
- 「子敏感度」卡片底下的「敏感点阶段性表现设置」进的是**另一个页面**：
  三栏「阶段（程度）」「方式（动作）」「关键词」——阶段/方式各一句提示词，关键词是自动判断
  方式用的词（自动保存，留空 = 内置默认，可单条/整部位/全部恢复默认）；
- 顶部状态栏：平静 / 发情 / 即将高潮 / 被寸止 / 余韵 / 高潮中，
  副标签带「排卵中」「寸止 N 次」「子敏感度·部位 段位」；
- 每 20 秒自动刷新一次，页面切到后台时不刷；
- 支持深浅色（跟随面板主题）。

本地看布局：把 `window.__CONCEPTION_DEMO__` 设成一份 state 快照，
不带面板直接打开 `index.html` 也能渲染（按钮只弹"这是预览"提示，不会真的操作）。

## 十五、已知边界

- 孕期/产后是**模拟设定**，不是医学模型；验孕的早晚期、假阴性只是剧情近似；
- 默认只读鱼之心和暗涌的数据；写操作只有：孕期暂停/恢复 PC 周期、
  孕期阶段写 PC 的 conditions/精力、魅魔开启后写 PC 精力与鱼之心依恋/亲密/欲；
  这些都可以在配置里分别关掉；
- PC 更新后如果 `cycle_clock` 结构变了，暂停/恢复会读不到而退回提示词兜底，
  日志里会有 warning；
- "她已经告诉他了"是从回话关键词推断的，偶尔会误判（比如她只是提到别人的怀孕）；
  想更准可以关掉 `self_test.tell_detect`，或者用 `/受孕记录` 对照；
- 插件自己的周期默认按自然偏移落锚点，想固定日期就填 `cycle.own_anchor_date`。
